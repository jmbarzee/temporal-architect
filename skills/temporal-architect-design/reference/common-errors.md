# Common Errors

Diagnostics from `twf check` and `twf parse`. Design-level mistakes are in [anti-patterns.md](./anti-patterns.md). Match programmatically on `kind` + `code`, which are stable across releases; messages are not.

## Resolve errors (kind: `resolve`)

| Code | Message | Cause | Fix |
|------|---------|-------|-----|
| `UNDEFINED_ACTIVITY` | `undefined activity: Foo` | Activity `Foo` is called but not defined | Add `activity Foo(...):` definition to the file |
| `UNDEFINED_WORKFLOW` | `undefined workflow: Foo` | Child workflow `Foo` is called but not defined | Add `workflow Foo(...):` definition to the file |
| `UNDEFINED_SIGNAL` | `undefined signal: Foo` | `await signal Foo` or `signal Foo:` case but no signal handler declared | Add `signal Foo(...):` declaration inside the workflow, before the body |
| `UNDEFINED_UPDATE` | `undefined update: Foo` | `await update Foo` or `update Foo:` case but no update handler declared | Add `update Foo(...) -> (Type):` declaration inside the workflow, before the body |
| `UNDEFINED_CONDITION` | `undefined condition: Foo` | `set Foo`, `unset Foo`, or `await Foo` but no condition declared | Add `condition Foo` inside the workflow's `state:` block |
| `UNDEFINED_PROMISE_OR_CONDITION` | `undefined promise or condition: Foo` | `await Foo` or `Foo:` case in `await one` but `Foo` is not a promise or condition | Add `promise Foo <- ...` in the workflow body or `condition Foo` in the `state:` block |
| `DUPLICATE_WORKFLOW` / `_ACTIVITY` / `_WORKER` / `_NAMESPACE` / `_NEXUS_SERVICE` | `duplicate workflow definition: Foo (first at line 3)` (etc.; `first at a.twf:3` when the first is in another file) | Two definitions of the same kind and name in one package; the first is kept, and the error lands on the later one | Remove or rename the duplicate |
| `DUPLICATE_SIGNAL` / `_QUERY` / `_UPDATE` / `_CONDITION` / `_NEXUS_OPERATION` | `duplicate signal in workflow Foo: Bar (first at line 3)` (etc.; `in nexus service Foo` for an operation) | A handler or condition declared twice in one workflow, or an operation twice in one nexus service; the first is kept, and the error lands on the later one | Remove or rename the duplicate |
| `DUPLICATE_ENDPOINT` | `duplicate nexus endpoint name "Foo": defined in namespace A and namespace B` (`in namespace A (first at line 3)` when both are in one namespace) | Same endpoint name declared twice, in multiple namespaces or in one; the first is kept | Use unique endpoint names |
| `CONDITION_RESULT_BINDING` | `condition "Foo" cannot have a result binding (-> identifier)` | `await Foo -> result` where `Foo` is a condition | Conditions are boolean — remove the `-> result` binding |
| `NEXUS_ASYNC_UNDEFINED_WORKFLOW` | `async operation Foo references undefined workflow: Bar` | Async nexus op points at a workflow that doesn't exist | Add the workflow or fix the name |
| `NEXUS_UNDEFINED_ENDPOINT` | `undefined nexus endpoint: Foo` | Endpoint referenced but not defined anywhere | Add a `nexus endpoint Foo:` in some namespace, or fix the name |
| `NEXUS_UNDEFINED_SERVICE` | `undefined nexus service: Foo` | Service referenced but not defined (in its package, following any qualifier + import) | Add a `nexus service Foo:` block, fix the name, or import the package that owns it |
| `NEXUS_NO_OPERATION` | `nexus service Foo has no operation Bar` | Operation name not in the service | Add the operation or fix the name |
| `WORKER_UNDEFINED_WORKFLOW` / `WORKER_UNDEFINED_ACTIVITY` / `WORKER_UNDEFINED_NEXUS_SERVICE` | `worker X references undefined ...` | Worker lists a name that doesn't exist | Add the definition or fix the name |
| `WORKER_REGISTERS_OPERATION` | `a worker registers a whole nexus service; Svc.Op names operation Op of Svc ...` | A worker entry names an operation (`nexus service Svc.Op`) | Register `nexus service Svc`; operations that must deploy apart belong in a separate service |
| `NAMESPACE_UNDEFINED_WORKER` | `namespace X references undefined worker: Y` | Namespace uses unknown worker | Add worker block or fix name |
| `ENDPOINT_PARAM_NOT_SUPERSET` | `nexus endpoint "X" must be parameterized by all of namespace N's template params; missing <param>` | An endpoint in a parameterized namespace omits one of its `{param}`s (e.g. static `BootstrapShard` inside `fabric-shard-{org}`), so its flat-global name would collide across the family | Add the missing `{param}`(s) to the endpoint name (e.g. `fabric-shard-{org}-BootstrapShard`) |
| `QUEUE_TEMPLATE_MALFORMED` | `task_queue "Q" of worker W in namespace N is not a well-formed template: <reason>`, the first of `{x} is not a parameter name` / `parameters must be separated by fixed text` / `stray or unclosed brace` / `fixed text begins with reserved prefix "P"` / `fixed text plus one byte per parameter exceeds 1000 bytes` | A worker `task_queue` with a `{param}` declares a [per-instance family](../topics/task-queues.md#per-instance-worker-families), and its queue breaks a rule. The placement drops out of routing, so calls that needed it also report routing errors | Make every brace group a plain name (`{sandboxId}`), separate parameters with fixed text, and avoid `/_sys/` and `temporal-sys-per-ns-` |
| `ENDPOINT_TASK_QUEUE_TEMPLATED` | `task_queue "Q" of nexus endpoint E in namespace N has a {P} parameter: an endpoint targets one task queue in its namespace` | A `{param}` in an endpoint `task_queue`. Name parameters never reach queues, and an endpoint cannot front a family | Use a static queue (`"bootstrap"`); reach a family through an async operation ([nexus.md](../topics/nexus.md#fronting-a-worker-family)) |
| `QUALIFIED_REF_WITHOUT_IMPORT` | `qualified reference uses package "p" with no matching import in package "q"` | A `p.Name` reference names a package `p` the file never `import`ed | Add `import "…/p"` (or fix the qualifier / alias) |
| `UNRESOLVED_IMPORT` | `import "github.com/acme/shop/billing/v2" is unresolved (no package "billing" in the tree); treated as external` | The import's path lies under no module in the run — warning, exit 0. The message quotes the **full import path**, then the path's assumed name (`.../billing/v2` → `billing`) | None required — the package is treated as external (see below). Fix the path if it was a typo |
| `UNUSED_IMPORT` | `unused import: "p" is never referenced` | An import that resolved but is never used — warning, exit 0 | Remove the import, or add the qualified reference you intended |
| `PACKAGE_OUTSIDE_MODULE` | `package fabric is not in a module; run "twf mod init <module path>" …` | A file with a `package` clause has no `twf.mod` above it; the file is ignored | Run `twf mod init <module path>` at the design's root (no argument suggests one) |
| `PACKAGE_NAME_MISMATCH` | `package clusterfabric must be named fabric, the assumed name of its import path …` | The clause differs from the directory's last path element (a trailing `/vN` dropped) | Rename the clause, or move the directory |
| `PACKAGE_CLAUSE_CONFLICT` | `directory fabric/v1 holds package fabric (f.twf) and package other (g.twf); g.twf is ignored` | One directory, two packages (or a clause mixed with clause-less files) | One package per directory: move or re-clause the file |
| `MODULE_FILE_INVALID` | `unknown directive "modul"; expected "module <path>"` | The `twf.mod` cannot be used; its module's files are ignored | Fix the `twf.mod`: exactly one `module <path>` line |
| `DUPLICATE_MODULE` | `module … is also rooted at …; this copy is ignored` | Two checkouts of one module in the inputs; the later one is ignored | Check only one copy, or remove the stale one |
| `DUPLICATE_PACKAGE` | `import path … is also the path of directory …; only … is used` | Two directories yield one import path (overlapping modules, or a case-only difference) | Rename or move one directory |
| `INVALID_PACKAGE_PATH` | `package directory kube (old) has the invalid import path …` | A package directory's name makes an invalid path (spaces, `:`, …) | Rename the directory |
| `IMPORT_NOT_FOUND` | `import "example.com/demo/fabirc/v1": module example.com/demo (at .) has no package fabirc/v1` | The path is under a module in the run, which has no such package — a typo or wrong case | Fix the path (a `did you mean` names a near match) |
| `IMPORT_NOT_LOADED` | `import "…" is not among the inputs; pass its package directory …` | The package is on disk but not passed — warning, treated as external | Pass the directory, or check the design's root |
| `DUPLICATE_IMPORT_NAME` | `import name fabric is already bound to "…" in package top (…); alias "…"` | Two imports share a qualifier, or one uses the package's own name | Alias one of them |
| `IMPORT_NEEDS_ALIAS` | `import "…/library-temporal-kube" needs an alias: …` | The path's last element cannot be a package name | `import kube "…"` |
| `SELF_IMPORT`, `INVALID_IMPORT_PATH` | `package … imports itself`; `invalid import path "./x": … is a local import path` | A package imports itself; a path is not a module path | Remove it; use the full import path |

### Packages, imports, and external references

A qualified reference resolves inside its imported package, so a missing symbol there raises the usual `UNDEFINED_*` / `NEXUS_*` error. Reach a genuinely external service by importing a package that isn't in the tree — never by local stubs.

## Parse errors (kind: `parse`)

Parse failures share the code `SYNTAX`; dispatch on the message until categorical parse codes land ([#32](https://github.com/jmbarzee/temporal-architect/issues/32)). The lexer's structural errors carry `LEX` instead (tagged below), and `twf check --lenient` still exits 1 on them: the file could not be tokenized.

| Message | Cause | Fix |
|---------|-------|-----|
| `<keyword> is not allowed in activity body` | Using a temporal primitive (`workflow`, `activity`, `timer`, `signal`, `await`, etc.) inside an activity definition or query handler | Move it to a workflow — temporal primitives need deterministic replay, which activities lack |
| `"<keyword>" cannot start a statement` | In a workflow, handler or nexus operation body, a line led by a keyword that begins no statement there: `options:` not under a call, `else:` not after an `if`/`switch`, `condition` outside `state:`, or a raw line such as `options = {}` or `state.count = 1`. Activity bodies accept such lines as pseudocode | Put the line where it belongs, or rename the variable |
| `update arrivals must be awaited: …` / `a timer must be awaited: …` | A bare `update Name` or `timer(d)` line | `await update Name` / `await timer(d)`, or bind it with `promise p <- …` |
| `a sync nexus operation receives no updates; …` | A bare `update Name` line in a sync nexus operation | Await the update in the workflow that handles it |
| `<signal\|query\|update> handler <Name> is declared after the workflow body's first statement; …` / `… is declared inside a handler; …` | A handler declaration below a body statement, inside a block, or inside another handler | Declare handlers above the workflow body's first statement |
| `a sync nexus operation declares no <signal\|query\|update> handlers; …` | A handler declaration in a sync nexus operation body | Declare it in a workflow |
| `import must come before the file's definitions` | An `import` line below a definition | Move the imports up, after the `package` clause |
| `expected the end of the line after <statement>, got …` | Something after a complete statement on its line: `break Missing`, `set Ready now`, `activity A(x) -> r extra`, a `-> r` on a `promise`. Also after a `condition`, `id_scheme:` or nexus `async` operation line | End the line after the statement; only a `# comment` may follow it. Bind a promise's result where it is awaited: `await p -> r` |
| `unexpected indent: …` | A line indented under a statement that takes nothing indented: a call with no `options:`, `close`, `set`, `id_scheme:`, a raw line (an activity's pseudocode included). Under a call or a send, a line other than its `options:` block or `id:` address | Align the line with the statement above, or nest it under a block header ending in `:`. Only comments may sit indented under any statement |
| `a promise takes no options:` / `an await takes no options:` | An `options:` block under a `promise` or `await` | Drop it; a promise-bound or awaited start uses the callee's `default_options:` |
| `expected ( after return type ->` | Return type not parenthesized: `-> Result` | Use `-> (Result)` — return types must be wrapped in parentheses |
| `expected ( after if` / `expected ( after for` | Missing parentheses around condition/iterator | Use `if (expr):` / `for (x in items):` |
| `unexpected token <tok> at top level` | Statement or keyword that doesn't start a workflow or activity definition | Ensure all top-level items are `workflow`, `activity`, `worker`, `namespace`, or `nexus service` definitions |
| `unexpected token <tok> in await one case` | Invalid case type inside `await one:` block | Cases must be `signal`, `update`, `timer`, `activity`, `workflow`, an identifier, or `await all` |
| `definition requires ':' and an indented body` | A bare declaration like `activity Foo(x) -> (R)` with nothing under it; `activity`/`workflow`/`sync` nexus op definitions always need a body. Often followed by a cascading `UNDEFINED_*`. Also raised by a dot in a namespace/endpoint name | Add `:` and an indented body; for a stub, one placeholder statement (`return Foo{}`, `log(...)`) |
| `unexpected OPTIONS in worker block` | `options:` on a worker definition | Move them to the worker's instantiation in a namespace — a worker is a reusable type set; the namespace deploys it |
| `unterminated string literal` (`LEX`) | A `"…"` string has no closing `"` before its line or the file ends — strings are single-line. Reported at the opening `"` | Close the string on the same line. Parens inside a closed string (`"org is required (bootstrap)"`) are fine |
| `unknown escape \n in string literal (only \" and \\ are escapes)` (`LEX`) | A backslash in a string is followed by anything but `"` or `\`, in a string literal or inside call arguments. Reported at the backslash | Write `\"` or `\\`, or drop the backslash |
| `unterminated argument list` (`LEX`) | A `(…)` group reaches the end of the file with a `(`, `{` or `[` unmatched. Reported at the opening `(` | Add the missing `)`, or balance the inner delimiters |
| `inconsistent indentation` (`LEX`) | A line dedents to an indentation no enclosing block uses (one tab, between blocks at none and two tabs). Reported at the line's first token; often followed by a cascading `SYNTAX` error | Indent the line to match the block it belongs to |
| `indented with spaces; .twf indents with tabs, one per level` / `indentation mixes tabs and spaces; …` (`LEX`) | A line's indentation holds a space. Reported at the first space, once per line | Indent with tabs, one per level (an editor's "convert indentation to tabs") |

## Validation diagnostics (kind: `validate`)

| Code | Severity | Cause | Fix |
|------|----------|-------|-----|
| `MISSING_TASK_QUEUE` | error | Worker instantiation has no `task_queue` option | Add `options: task_queue: "..."` to the worker instantiation |
| `MISSING_ENDPOINT_TASK_QUEUE` | error | Nexus endpoint instantiation has no `task_queue` | Add the option to the endpoint instantiation |
| `EXPLICIT_ROUTING_MISMATCH` | error | An activity/workflow call's explicit `task_queue` (or its target's `default_options:` one) matches no queue whose worker registers the target in the caller's namespace. A queue with parameters matches by shape (`… but no worker polling a queue of that shape in namespace N registers it`); a learned queue needs a family (`… has a learned task_queue "{lease.queue}", but no per-instance worker family in namespace N registers it; a .twf learned queue names a family member (model a static set as a family or as static calls)`) | Fix the queue or register the target on a matching worker in that namespace. `"workers-{req.region}"` never reaches static `"workers-us"`: model the set as a family or as static calls. A `task_queue` cannot cross namespaces — use Nexus |
| `IMPLICIT_ROUTING_MISMATCH` | error | An activity/workflow is called with no `task_queue` (call site or target `default_options:`) and no worker on the caller's queue (same deploy key, for a family) in the caller's namespace registers it. For a family the message reads `… is not on any worker polling a queue of the shape of "Q" in namespace N (inherited from workflow W)` | Add the target to a worker on that queue in that namespace, or set `task_queue` on the call or in the target's `default_options:`; for another namespace, use Nexus |
| `WORKER_DUPLICATE_TYPE_NAME` | error | A worker registers one name twice for a kind: two workflows, activities, or nexus services from different packages (`worker W registers workflow a.Run and workflow b.Run under one name, "Run"; Temporal registers types by name, not package, so one worker can hold only one of them`), or the same entry repeated (`worker W registers workflow Run twice; Temporal registers each name once per worker`) | Drop a repeat; put same-named types on workers polling different task queues — a package qualifier never reaches Temporal |
| `ENDPOINT_SERVICE_LINKAGE` | error | Endpoint routes to a task queue but no worker on that queue in the endpoint's namespace registers the service | Register the service on a worker for the endpoint's queue in the endpoint's namespace |
| `TASK_QUEUE_MISMATCH` | error | Two workers share a queue in one namespace but register different workflow/activity sets, or both register nexus services but different ones (a worker with no services polls no Nexus tasks and is not compared; message `…register different nexus service sets`). Queues with the same deploy key are one: `"sandbox-{sandboxId}"` and `"sandbox-{id}"`, or two bare families. Differing spellings are both named: `workers A and B on task queues "Q1" and "Q2" in namespace N have different type sets` | Make the type sets identical, or use distinct queues (distinct fixed text, for families) |
| `TASK_QUEUE_IDENTICAL` | warning | Two workers register identical workflow, activity, and service sets on the same queue (same deploy key) in one namespace (redundant); differing spellings are both named, as above | Drop one of the workers |
| `TASK_QUEUE_OVERLAP` | hint | Two placements with different deploy keys, at least one a family, that one concrete queue could fit: `task_queue "sandbox-{sandboxId}" of worker sidecar and "sandbox-pool" of worker pool could name the same queue in namespace N` (the later-declared placement first). Coherence cannot see it | Give the static queue or the family distinct fixed text (`"pool"`) |
| `INSTANCE_QUEUE_NO_START_TIMEOUT` | hint | An activity call that names its queue reaches a family with no bound on its wait: `activity A routes to the per-instance queue family "Q" in namespace N with neither schedule_to_start_timeout nor schedule_to_close_timeout: if instances are short-lived, a task for a vanished instance waits until the calling workflow's own timeout or cancellation` | Short-lived instances: set `schedule_to_start_timeout` and handle its failure. Long-lived fleet: monitor schedule-to-start latency, and leave it |
| `INSTANCE_FAMILY_HOSTS_WORKFLOW` | hint | A family worker registers a workflow, whose tasks have no schedule-to-start timeout: `worker W hosts workflow X on the per-instance queue family "Q" in namespace N: if an instance goes away for good, its executions stall until their own timeout; short-lived families should host workflows on a shared queue` | Move the workflow to a worker on a shared queue; a long-lived family may keep it on purpose |
| `INSTANCE_FAMILY_VERSIONED` | hint | A family with `versioning: deployment` or `build_id`: `worker W in namespace N is a per-instance family on "Q" with versioning: deployment; a deployment version accepts at most 100 distinct task queues over its life, so new instance queues are refused once that many have registered` (for `build_id`: `…; every new instance queue needs its own versioning API call (off by default, not on Cloud)`) | Drop `versioning` from the family; a small fixed value set may keep it |
| `INSTANCE_FAMILY_HOSTS_NEXUS_SERVICE` | warning | A family worker registers a Nexus service, which no static endpoint reaches: `worker W registers nexus service S on the per-instance queue family "Q" in namespace N, but a .twf endpoint targets one static queue, so no endpoint in this design reaches it; put the service on a static queue and route on from an async operation's workflow` | Move the service to a static queue; its async operation's workflow calls the family ([nexus.md](../topics/nexus.md#fronting-a-worker-family)) |
| `NEXUS_CALLER_NOT_ALLOWED` | error | A nexus call originates in a namespace its endpoint's `allowed_caller_namespaces` omits — including the endpoint's own namespace | Add the caller's `.twf` namespace name (not a Cloud ID) to the list, or call from a listed namespace |
| `UNCOVERED_WORKFLOW` / `UNCOVERED_ACTIVITY` / `UNCOVERED_SERVICE` | warning | Definition exists but no instantiated worker registers it | Register on a worker or remove the unused definition |
| `UNINSTANTIATED_WORKER` | warning | Worker defined but never instantiated in any namespace | Instantiate it in a namespace, or remove the worker |
| `EMPTY_WORKFLOW` / `EMPTY_ACTIVITY` / `EMPTY_WORKER` / `EMPTY_NAMESPACE` | warning | Block has no body / no registrations / no instantiations | Add content or remove the empty block |

`id_scheme:` and addressed-send codes (`ID_*`, `TYPE_NEEDS_ID`, `ADDRESS_MISPLACED`, `NOT_A_PARENT`, …) are tabled in `twf spec resolution-and-errors`; the design rules behind them are in [workflow-id-schemes.md](../topics/workflow-id-schemes.md).

`twf help` documents the JSON envelope that carries these diagnostics (`diagnostics[].code`).
