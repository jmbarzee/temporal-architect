# discovery

The Perl signals the design skill's [reverse engineering](../../temporal-architect-design/reference/reverse-engineering.md#language-signals) reads code by. Call sites read backward through the [reference index](../SKILL.md#reference-index): `Temporalio::Workflow::execute_activity` is an `activity` call, `execute_child_workflow` a `workflow` call, `execute_operation` a `nexus` call, `Temporalio::Exception::Application->throw` in the run a `close fail`. Names read back through [Wire names](../SKILL.md#wire-names). Paths below are in sdk-perl source at `55816a1` (`sdk/lib/Temporalio/`).

## Project roots

- A `cpanfile`, `Makefile.PL` or `dist.ini` requiring `Temporalio::Client`, `Temporalio::Worker` or `Temporalio::SDK` (dist `Temporalio-SDK`, `sdk/dist.ini:3`) marks a root that uses Temporal. sdk-perl is not on CPAN, so a manifest may leave it out: then the directory whose modules `use Temporalio::Worker` or declare `:isa(Temporalio::Workflow::Definition)` is the root. Its top-level Perl namespace, else the repo path, is the path `twf mod init` takes; ask when neither fits. Each such directory is its own root; `t/` and `t/lib/` hold tests and their fixtures, not the design.

## Registration

- `Temporalio::Worker->new(client =>, task_queue => 'q', workflows => [...], activities => [...], nexus_services => [...])` (`Worker.pm:36-40`) starts a worker on `q` in its client's namespace: `Temporalio::Client->connect($target, namespace => …)`, `'default'` when unset (`Client.pm:816`). A namespace or queue read from config or the environment (`Temporalio::EnvConfig::ClientConfig->load_client_connect_config`, `EnvConfig/ClientConfig.pm:44`; `$ENV{…}`) cannot be resolved from code: ask, or leave it to the stitch's topology. Its other keys read back through [worker.md](./worker.md#worker-options--temporalioworker-new) into the namespace worker's `options:`; `disable_eager_activity_execution => 1` is `request_eager_execution: false` on every activity call its workflows make.
- The types one `Temporalio::Worker->new` registers make one `worker` block ([worker.md](./worker.md#registration)), annotated `@sdk(perl, "<path>")` with the module that builds it. A `<Worker>Types.pm` whose `sub worker ($client, %opts)` returns the worker is that set, shared by the worker process and its tests: `ApprovalTypes::worker` is `worker approvalTypes`, and `ApprovalTypes.pm` is the path. A test's worker gives the test's queue, not the deployment's, and classes only `t/lib/` registers are fixtures.
- `workflows` lists `Temporalio::Workflow::Definition` classes, its `:Run` method named `run` registering the package basename, any other the method name, unless `:Run('Name')` names it. `activities` lists `Temporalio::Activity::Definition` classes or built instances, each registering every `:Defn` method of its class by `:Defn('Name')`, else the method name as written, so an unnamed snake_case activity is a snake_case `.twf` activity ([SKILL.md](../SKILL.md#wire-names)).
- A `:Signal`, `:Query` or `:Update` method of a workflow class declares a `signal`, `query` or `update` of that workflow, named by its attribute's name, else the method name. Its params are the method's, positional, its result the query's or update's return, and its body the method's statements less the arrival record (`$xs->add(…)`, `$acks++`). The `field`s the handlers and `run` share, less its `Arrivals` and arrival counts, are its `state:`. A `'unfinished_policy=ABANDON'` kwarg is `unfinished_policy: abandon`, and a `# description: "…" (no Perl form)` comment beside the method is its `description`.
- An `:UpdateValidator('Name')` method (`Workflow/Definition.pm:86`), a `dynamic=1` handler (`Workflow/Definition.pm:160-167`), a handler registered at runtime with `Temporalio::Workflow::set_signal_handler`, `set_query_handler`, `set_update_handler` or their `set_dynamic_*` forms (`Workflow.pm:390-459`), and a workflow's `:VersioningBehavior` (`Workflow/Definition.pm:118`) have no `.twf` form: record each in prose with its `file:line`.
- A plain `sub id (…)` in a workflow's package, returning an interpolated string that every start of it passes as `id =>`, is its `id_scheme:`: each hole is the start's argument, named from the workflow's params (`ShipItem::id($order->{id}, $item->{id})` → `"ship-{order.id}-{item.id}"`). A `start_options` sub's `id_reuse_policy` and `id_conflict_policy` are its `default_options:` ID policies ([workflow-def.md](./workflow-def.md#id_scheme)).
- An options sub that every call of one activity or workflow spreads first is that definition's `default_options:`; the keys a call adds after it are that call's `options:` ([options.md](./options.md#definition-level-default_options)).
- A child param its parent fills with `Temporalio::Workflow::info->{workflow_id}`, used only as a signal target, is `id: parent` on that send: drop it from the child's signature ([signal-send.md](./signal-send.md#id-parent--unsupported)).
- A queue built by an instance-key sub (`sub queue ($sandbox_id) { "sandbox-$sandbox_id" }`) is a [family](./worker.md#per-instance-worker-families) worker.
- Each `nexus_services` entry, a `Temporalio::Nexus::Definition` class, is a Nexus service on that worker, named by `:NexusService('Name')`, else the class basename (`Nexus/Definition.pm:94-101`). Each `:SyncOperation` or `:WorkflowRunOperation` method is an operation, named by its attribute, else the method name (`:81-83`). A `:WorkflowRunOperation` returning `$ctx->start_workflow('W', …)` is an `async` operation backed by `W`; a `:SyncOperation` a `sync` one, its client forms read back through [nexus-service-def.md](./nexus-service-def.md#sync).
- `Temporalio::Workflow::create_nexus_client(endpoint => 'Ep', service => 'Svc')` names, as strings, the endpoint and service of every `nexus` call made through it, and `execute_operation('Op', …)` the operation; follow a variable to its value.
- A worker built behind a factory or config loader: follow it to the `Temporalio::Worker->new`.

## Concurrency

| Perl | `.twf` |
|------|--------|
| `:Signal` / `:Update` method whose body ends with `$xs->add(…)` on an `Arrivals` | handler, its body less the `add` ([signal-handler.md](./signal-handler.md), [update-handler.md](./update-handler.md)); a count it bumps (`$acks++`) and a waiter decrements once per take (`$acks > 0` … `$acks--`) is the same queue, while one never decremented, or reset, is plain `state:` |
| `await $xs->take` | `await signal\|update Name -> (…)`: one value binds one name, `my ($a, $b) = @{ await $xs->take }` binds several, and an `add(1)` arrival binds none ([await-signal.md](./await-signal.md)) |
| `my $p = $xs->take`, awaited later | `promise p <- signal\|update Name` ([promise.md](./promise.md)) |
| `Future->needs_all(…)`; over `map { … } @$items` | `await all`, branches in argument order; a `for` fan-out inside ([await-all.md](./await-all.md)), with a comment that the first failure cancels the pending branches |
| `Future->wait_all(…)`, each future checked after | `await all` ([await-all.md](./await-all.md)) |
| one `wait_condition` over `$xs->ready`, an arrival count (`$acks > 0`), `$p->is_ready`, `$timer->is_ready` and fields, then the first ready one in check order wins (`claim`, `$acks--`, `await $p`) | `await one`, cases in that order ([await-one.md](./await-one.md)); a losing inline timer's `->cancel` is part of the race (spec 06), not a statement; when a message case follows a non-message one, comment that a tie goes to the message case ([#474](./await-one.md#tie-order-474)) |
| `wait_condition(sub { c }, timeout => $s)`, catching `Temporalio::Exception::Timeout` | `await one` with a `c` case, then a `timer($s)` case holding the catch's body, with a comment that job order decides a tie, not listed order (`Workflow/Runner.pm:1990-2006`) |
| `Future->wait_any(…)` | `await one`, with a comment that the first to complete wins, not the first listed, and that the losers are cancelled, an activity's cancellation requested ([await-one.md](./await-one.md)) |
| a scalar field set in a handler, `await Temporalio::Workflow::wait_condition(sub { $flag })` | `condition`, `set` in the handler ([condition.md](./condition.md)); read as `await signal Name` only with a comment that it is one-shot: the flag holds one arrival, and later ones are lost |
| a future held and awaited later (`start_activity`, an unawaited `execute_child_workflow` or `execute_operation`, `Temporalio::Workflow::sleep`) | `promise` ([promise.md](./promise.md)) |
| `await` on the call itself | synchronous call |
| `await start_child_workflow(…)` without `parent_close_policy => 'abandon'`, its handle signaled or its `->result` awaited | `promise p <- workflow` ([workflow-call.md](./workflow-call.md), [signal-send.md](./signal-send.md)) |
| `await start_child_workflow(…)` with `parent_close_policy => 'abandon'`, `->result` never awaited | `detach workflow`; without `cancellation_type => 'abandon'` the caller's cancellation still reaches it, so record that in prose ([detach.md](./detach.md)) |
| `$ctx->client->start_workflow` in a `:SyncOperation`, `->result` never awaited | `detach workflow` ([detach.md](./detach.md)) |
| `start_operation` with `cancellation_type => 'abandon'`, `->result` never awaited | `detach nexus` ([detach.md](./detach.md)) |
| `Temporalio::Workflow::continue_as_new(undef, args => [...])` | `close continue_as_new(args)` ([close.md](./close.md)); with a type name, onto another type, record it in prose (`Workflow.pm:503`) |
| `await Temporalio::Workflow::sleep($s)` | `await timer($s)` in seconds ([await-timer.md](./await-timer.md)) |

## Codegen

- No forward variant generates code ([SKILL.md](../SKILL.md#orient)).
- Under the default converter a payload is plain data ([types.md](./types.md)): a hashref is a user type keyed by its field names, `!!$x` or `\1` a `bool`, a `Temporalio::Payload::RawBytes` `bytes`. A string or number is `decimal`, `time` or `duration` only where a name or comment says so.
- A protobuf message class (one with `descriptor` and `to_hashref`) travels through the default converter's `json/protobuf` and `binary/protobuf` encodings (`Converter/Payload.pm:23-35`, `Converter/Payload/JsonProtobuf.pm:20-23`): the payload types come from the `.proto` that protobuf-perl's `protobuf-gen-perl` compiles ahead of time or `Protobuf::Class::Generator->build` loads at runtime.
- A `Makefile`, `justfile` or `dist.ini` plugin names any other generator.
