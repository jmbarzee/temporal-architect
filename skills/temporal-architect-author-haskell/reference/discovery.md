# discovery

The Haskell signals the design skill's [reverse engineering](../../temporal-architect-design/reference/reverse-engineering.md#language-signals) reads code by. Call sites read backward through the [reference index](../SKILL.md#reference-index): `executeActivity` is an `activity` call, `executeChildWorkflow` a `workflow` call, `executeNexusOperation` a `nexus` call. Names read back through [Wire names](../SKILL.md#wire-names). Paths are in the SDK's source at `e57a0ae`, as in [SKILL.md](../SKILL.md#orient); `flake.nix` is the SDK's root.

## Project roots

- A `.cabal` file or hpack `package.yaml` whose `build-depends` (or `dependencies`) names `temporal-sdk` marks a root that uses Temporal. Its package `name:`, else the repo path, is the path `twf mod init` takes; ask when neither fits. Each package a `cabal.project` lists under `packages:` is its own root, less the SDK's own (`temporal-sdk`, `temporal-sdk-core`, `temporal-api-protos`); a `test-suite` component is not a root of its own.
- **The SDK's pin.** A `cabal.project` that lists a clone's `sdk`, `core` and `protos` directories as local packages, as `corpus/cabal.project` does, pins the commit that clone checks out (a submodule, or a revision its build script names); a `source-repository-package` pins its `tag:`. A bare Hackage bound (`temporal-sdk ==2025.10.1.0`) is the one release, which has no Nexus. A `flake.nix` with an `hs-temporal-sdk` input composing its `haskellOverlays.hs-temporal-sdk` or `overlays.haskell-development` (`flake.nix:94-125`), as the cookbook's does, pins the input's `rev` in `flake.lock`. Read call shapes at that pin, not at `e57a0ae`, when they differ.

## Registration

- `startWorker client (cfg settings)` (`Worker.hs:780`) starts a worker on the `setTaskQueue` in `settings`, in its `setNamespace`, each `"default"` when unset (`Worker.hs:197-202`, `core/src/Temporal/Core/Worker.hs:627-631`). A namespace or queue read from config or the environment (`lookupEnv`, a config file, a CLI flag) cannot be resolved from code: ask, or leave it to the stitch's topology. The other setters read back through [worker.md](./worker.md#worker-options--configm-setters) into the namespace worker's `options:`.
- One `configure env defs settings` (`Worker.hs:196`) makes one `worker` block ([worker.md](./worker.md#registration)), annotated `@sdk(haskell, "<path>")` with the module file that calls it. A function returning the `WorkerConfig` with the settings left to its caller is that set, shared by the worker process and its tests: `approvalTypes = configure () approval` is `worker approvalTypes`, and its file is the path. With no `startWorker` applying it in the slice, there is no namespace or queue to recover; a test's worker gives the test's queue, not the deployment's, and workflows only a test registers are fixtures, not the design.
- `defs` is one `ProvidedWorkflow` or `ProvidedActivity`, a tuple of up to six, or `Definitions` joined with `<>` (`Worker.hs:214-278`). Each `provideWorkflow codec "Name"` is a `workflow Name`, each `provideActivity codec "Name"` an `activity Name`; params are the lambda's, positional, and the result the `Workflow` or `Activity env` result type ([workflow-def.md](./workflow-def.md), [activity-def.md](./activity-def.md)). Types read back through [types.md](./types.md): a `Binary` codec carries `bytes`, a `Protobuf` codec the messages of [Codegen](#codegen).
- **Template Haskell.** `$(registerWorkflow 'fn)` and `$(registerActivity 'fn)` register `fn` under `"Module.fn"`, `Module` the module that defines it (`TH/Internal.hs:51-57,72`); the `register`, `registerWithConfig`, `registerAdvanced`, `registerWorkflows` and `registerActivities` splices do the same for every function in their `[d| … |]` quote with a type signature returning `Workflow a` or `Activity env a`, and skip those without one (`TH.hs:570-636,798-826,916-944,1001-1002`). A `.twf` name cannot hold a `.`, so a default-named type has no `.twf` spelling (`twf spec tokens-and-keywords`): ask the user, never rename it silently. `registerWorkflowWithOptions 'fn conf` and `registerActivityWithOptions 'fn conf`, or `registerWithConfig`'s per-function configs, take the name from `workflowConfigNameOverride` or `activityConfigNameOverride` when `Just` (`TH/Classes.hs:103,180-184`). A hand-written `Fn` instance's `fnName` is the name (`TH.hs:305-320`).
- **Aliases** (`workflowConfigAliases`, `activityConfigAliases`) register further names for the same definition, and only through `discoverDefinitions` (`TH.hs:521-541`): each is one more `workflow` or `activity` with the same params and body, with a comment that it is an alias. A TH-registered function is called through its generated constructor, the function's name capitalized (`TH/Internal.hs:43-48`): `executeChildWorkflow MyWorkflow …` calls `myWorkflow`'s registration.
- `configure env (discoverDefinitions @env $$(discoverInstances) $$(discoverInstances))` registers every TH-registered workflow and activity in scope where it is spliced, less activities whose environment is not `env`, which it drops silently (`TH.hs:515-541`). Read the instances in scope, not the call: the `worker` block lists each, with a comment that the set is what that module imports.
- Each `KnownSignal "Name" codec`, `KnownQuery "Name" codec` and `KnownUpdate codec "Name"` a workflow body passes to `setSignalHandler`, `setQueryHandler` or `setUpdateHandler` declares a `signal`, `query` or `update` of that workflow ([signal-handler.md](./signal-handler.md), [query-handler.md](./query-handler.md), [update-handler.md](./update-handler.md)). Its params are the type's list, positional, its result the query's or update's type, and its body the handler's statements less the arrival record (`A.add`, or a counter's increment). The `StateVar`s the handlers and the body share, less its arrivals and counters, are its `state:`.
- An update's validator (`setUpdateHandler ref h (Just v)`, `Workflow.hs:1295-1307`) and `setDefaultQueryHandler`, which serves any unmatched query name (`Workflow.hs:1273-1277`), have no `.twf` form: record each in prose with its `file:line`.
- An ID function returning a `WorkflowId` (`shipItemId orderId itemId = WorkflowId ("ship-" <> orderId <> "-" <> itemId)`) is the callee's `id_scheme:` (`"ship-{orderId}-{itemId}"`), and the start-options function beside it its `default_options:` ([workflow-def.md](./workflow-def.md#id_scheme)). An options value shared by every call of one definition is its `default_options:`, and a call's record update over it the call's `options:` ([options.md](./options.md#definition-level-default_options)).
- A queue built by an instance-key function (`sandboxQueue sandboxId` → `TaskQueue ("sandbox-" <> sandboxId)`) is a [family](./worker.md#per-instance-worker-families) worker.
- Each `addNexusServiceHandler h` in a worker's settings (`Worker.hs:541`) is a Nexus service on that worker: `h`'s `serviceName` names it, and each key of its `operations` map is an operation (`Nexus/Worker.hs:38-41`). An operation whose handler answers its start with `syncSuccess`, as the [`syncOperation`](./nexus-service-def.md#sync) helper does, is a `sync` operation, its param the decoded input, its result the encoded output, and its body the function's, read back through that section's table. One that answers `asyncSuccess` is hand-rolled, which the SDK has no form for ([nexus-service-def.md](./nexus-service-def.md#async)): it is an `async` operation backed by the workflow its handler starts; confirm that with the user.
- `makeNexusClient "Ep" "Service"` names the endpoint and service of every `nexus` call made through it; an endpoint from config cannot be resolved from code. The input and result types are what the caller encodes and decodes, since the call is untyped ([nexus.md](./nexus.md)).
- A `WorkerConfig` built behind a helper or a record of settings: follow it to the `configure`.

## Concurrency

| Haskell | `.twf` |
|---------|--------|
| `setSignalHandler` / `setUpdateHandler` whose body calls `A.add xs v` on an `Arrivals`, a signal's last, an update's before its result | handler, its body less the `A.add` ([signal-handler.md](./signal-handler.md), [update-handler.md](./update-handler.md)); a `StateVar Int` it increments and a waiter decrements once per take (`(> 0) <$> readStateVar acks` … `modifyStateVar acks (subtract 1)`) is the arrivals of a no-param message, while one never decremented, or reset, is plain `state:` |
| `A.take xs` | `await signal\|update Name -> (…)`, a tuple matched into its names; `Arrivals ()` binds none ([await-signal.md](./await-signal.md)) |
| `p <- A.begin xs`, `A.takeAt xs p` later | `promise p <- signal\|update Name` ([promise.md](./promise.md)) |
| a handler appending to a `StateVar [a]`, each waiter `waitCondition (not . null <$> readStateVar q)` then popping | `await signal\|update Name`, with a comment that two waiters at once are served newest first, as a woken condition runs ([await-signal.md](./await-signal.md)) |
| a `StateVar Bool` a handler sets (`writeStateVar flag True`; `False` is `unset`), awaited by `waitCondition (readStateVar flag)` | `condition` + `set` ([condition.md](./condition.md)), with a comment that repeated arrivals collapse into one: it is no `await signal` |
| `concurrently a b`, `independently a b`, `runConcurrentWorkflowActions`, `sequenceConcurrently`; `traverseConcurrently` / `mapConcurrently` / `forConcurrently` and their `_` forms over `items` (`Workflow.hs:1783-1853,1924-1940`) | `await all`, branches in argument order; a `for` fan-out inside ([await-all.md](./await-all.md)) |
| `race a b`, nested to the right (`race a (race b c)`), or `race_` (`Workflow.hs:1754-1777`) | `await one`, cases in that order ([await-one.md](./await-one.md#cases)), with a comment that a signal or update case, or a condition its handler sets, beats a timer, activity, child or Nexus result in the same activation whatever the listing, when the handler reaches its `A.add` or condition write without blocking ([await-one.md](./await-one.md#tie-order-at-e57a0ae)) |
| a `race` branch `waitCondition (A.ready xs w)` after `w <- A.begin xs`, the winner `A.claim`, every loser `A.leave` | a `signal\|update Name` case; a `w` begun earlier and not left is a promise's case ([await-one.md](./await-one.md#cases)) |
| a `race` branch `waitCondition (readStateVar c)` | a `c:` case ([condition.md](./condition.md)) |
| a `race` branch `traverse_ wait t` over `t <- createTimer d`, or `sleep d` | a `timer(d)` case, whether the losing timer is cancelled or left to fire; a `t` created before and read across rounds or after is `promise t <- timer(d)` with a `t:` case, which losing never cancels |
| `startActivity`, `startChildWorkflow` (no `ParentClosePolicyAbandon`), `startNexusOperation` or `createTimer` bound, `wait`ed or signaled later | `promise` ([promise.md](./promise.md)) |
| `executeActivity`, `executeChildWorkflow`, `executeNexusOperation` | synchronous call |
| `startChildWorkflow` with `parentClosePolicy = ParentClosePolicyAbandon`, then `waitChildWorkflowStart`, the handle never waited | `detach workflow` ([detach.md](./detach.md)); with `cancellationType = ChildWorkflowCancellationTryCancel` the caller's cancellation still reaches it, and without `waitChildWorkflowStart` a failed start goes unseen: record either in prose |
| `C.start` in a sync Nexus handler, `C.waitWorkflowResult` never called | `detach workflow`; with it, a `workflow` call ([nexus-service-def.md](./nexus-service-def.md#sync)) |
| `startNexusOperation`, its `Task` never waited | `detach nexus`, with a comment that the call is the forward form of an unsupported detach: the caller's cancellation reaches the operation, and a failed start goes unseen ([detach.md](./detach.md)) |
| `signal h ref args` on a `ChildWorkflowHandle` | `signal h.Name(args)` on the `promise h <- workflow`; on a `getExternalWorkflowHandle wid mrid`, `signal Type.Name(args)` with `id:` (and `run_id:` from a `Just`), the type the ID function's scheme belongs to, and `id: parent` from `info`'s `parent`; for a learned ID (`WorkflowId stuck.workflowId`), the type with an ID function building it, else the workflow whose module defines the `KnownSignal` ([signal-send.md](./signal-send.md)) |
| `continueAsNew wf opts args` | `close continue_as_new(args)` ([close.md](./close.md)); onto another workflow, record it in prose |
| the body's final `pure r` | `close complete(r)` ([close.md](./close.md)) |
| `throwM ApplicationFailure {…}`, an uncaught exception | `close fail(…)` ([close.md](./close.md)) |
| `sleep d`, or `createTimer d` waited at once | `await timer(d)` ([await-timer.md](./await-timer.md)) |
| `withHeartbeat codec \beat _ -> …`, `beat x` | `heartbeat(x)` ([heartbeat.md](./heartbeat.md)) |
| `let x = expr`, `x <- action`, `writeStateVar x v` | `x = expr` ([control-flow.md](./control-flow.md)) |
| `if c then … else …`, `when c …` | `if (c):` … `else:` |
| `for_ items \item -> …` | `for (item in items):` |
| a local `loop` that recurses while a condition holds (`when (retries < max) do …`) | `for (retries < max):` |
| `forever …` | `for:` |
| `case v of` | `switch (v):` |
| a recursive `loop` that returns / calls itself | `break` / `continue` |

## Codegen

- No forward variant generates code ([SKILL.md](../SKILL.md#orient)).
- Template Haskell generates each registration's constructor and `Fn` instances ([Registration](#registration)); `bringRegisteredTemporalFunctionsIntoScope` only splits the declaration groups (`TH.hs:508-509`) and maps to nothing.
- A definition with the `Protobuf` codec takes `proto-lens` messages (`Payload.hs:219-223`): its payload types come from the `.proto` files the package's `proto-lens-setup` custom setup or `proto-lens-protoc` run compiles.
- A `.cabal` file's `build-tool-depends` and `custom-setup`, a `package.yaml`'s `build-tools`, or a `flake.nix` derivation name any other generator. No Nexus contract codegen exists at the pin.
