# discovery

The Rust signals the design skill's [reverse engineering](../../temporal-architect-design/reference/reverse-engineering.md#language-signals) reads code by. Call sites read backward through the [reference index](../SKILL.md#reference-index): `ctx.execute_activity(T::m, …)` is an `activity` call, `ctx.start_child_workflow(W::run, …)` a `workflow` call, `ctx.start_nexus_operation(…)` a `nexus` call, and a `.signal(W::s, …)` on a `StartedChildWorkflow` or on `ctx.external_workflow(id, run_id)` a `signal` send, whose `external_workflow` ID is a constructed `id:` when an ID function renders it, a learned one when a variable holds it, and `id: parent` from `ctx.info().parent()` ([signal-send.md](./signal-send.md#type-head-by-id)). Names read back through [Wire names](../SKILL.md#wire-names), and payload types through [types.md](./types.md): a field's `.twf` name is its serde name, after `rename_all` or `rename`. A call's options read back through [options.md](./options.md): a child's `task_queue(ctx.task_queue())` is the caller's, so no `task_queue`; one function every call of a definition starts from is that definition's `default_options:`, and a call's own changes to it its `options:`. Paths below are in sdk-rust source at `v1.1.2` (`crates/`).

## Project roots

- A `Cargo.toml` that depends on `temporalio-sdk` marks a root that uses Temporal. Its `[package] repository` without the scheme (`github.com/acme/orders`), else the repo path, is the path `twf mod init` takes; ask when neither fits. A `[workspace]` joins several member crates, each its own root; a crate only tests or examples use is not a root of its own.

## Registration

- `WorkerOptions::new("q")` (`sdk/src/lib.rs:186-194`) starts a worker on `q` once `Worker::new(&runtime, client, options)` runs it (`:905-909`), in the client's namespace: `ClientOptions::new("ns")`, which has no default (`client/src/options_structs.rs:196-203`). A namespace from `ClientOptions::load_from_config(…)`, a TOML profile or the environment, `"default"` when the profile has none (`client/src/envconfig.rs:17,21-37`), or a queue from `std::env::var`, cannot be resolved from code: ask, or leave it to the stitch's topology. Its other setters read back through [worker.md](./worker.md#worker-options) into the namespace worker's `options:`: the `tuner`'s four slot suppliers are the `max_concurrent_*_executions`, one left at the default `FixedSizeSlotSupplier::new(100)` an unset key, and `deployment_options` with `use_worker_versioning(true)` is `versioning: deployment`, else `none`.
- The types one `WorkerOptions` registers make one `worker` block ([worker.md](./worker.md#registration)), annotated `@sdk(rust, "<path>")` with the file that registers them. A `<worker>_types()` function is that set, shared by the worker binary and its tests: `batch_types()` is `worker batchTypes`, and its file is the path. With no `Worker::new` running it in the slice, there is no namespace to recover; a test's worker gives the test's queue, not the deployment's, and workflows only a test registers (the corpus's `fixtures.rs`) are fixtures, not the design.
- `.register_workflow::<W>()?` (`sdk/src/lib.rs:488`) registers `W`'s `#[workflow_methods]` impl, named for its struct unless `#[run(name = "…")]` (`macros/src/workflow_definitions.rs:644-648`). Its params are the one input after the context of `#[init]`, else of `#[run]`: none, one, or a `MultiArgsN` destructured into its names, positional ([workflow-def.md](./workflow-def.md)); its return is `WorkflowResult<T>`'s `T`, none for `()`. An associated `fn id(…)` that formats the ID is its `id_scheme:`, one hole per argument, and a `start_options` setting `id_reuse_policy` or `id_conflict_policy` its `default_options:` ([options.md](./options.md#workflow-id-policies)).
- `.register_workflow_with_factory::<W, _>(f)?` (`sdk/src/lib.rs:514-529`) registers `W` as `register_workflow` does; `W` has no `#[init]`, so the factory's value is its initial state. `.register_wasm_workflow(component)`, behind the `wasm-workflows` feature (`:547-551`), registers workflows compiled elsewhere: read their source, or ask.
- `.register_activities(instance)` registers every `#[activity]` method of its `#[activities]` impl, `.register_activity::<A>(Arc::new(…))` one (`sdk/src/lib.rs:472-486`). An activity is named by `#[activity(name = "…")]`, else `#[activity(definition = D)]`'s declared name, else `"Type::method"` (`macros/src/activities_definitions.rs:164-172,541-549`), e.g. `"BatchActivities::count"`, which is no `.twf` identifier: ask, or name it for the method in PascalCase (`Count`) and say the wire name differs, since a caller in another SDK must send `"BatchActivities::count"`. Its params are the method's after the `ActivityContext`, positional ([activity-def.md](./activity-def.md)). An `#[activity_definitions]` impl declares an activity another SDK's worker implements: the `.twf` activity, with no Rust worker registering it.
- A `#[signal]`, `#[update]` or `#[query]` method of the impl declares a `signal`, `update` or `query` of that workflow, named by its `name =` else the method name. Its params are the one input after the context, a `MultiArgsN` destructured positionally; its result the update's or query's return, `Result`'s `Ok` type when it returns one; and its body the method's statements, sync on `&mut self` or async through `ctx.state_mut`, less the arrival record (`xs.add(…)`, or a counter's `acks += 1`). The struct's fields, less those `#[init]` sets from its input (the params), its `Arrivals` and counters, are its `state:`, valued as `#[init]` or `Default` builds them. The attributes accept only `name` (`macros/src/workflow_definitions.rs:270-290`), so no `description` or `unfinished_policy` reads back.
- An `#[update_validator(method)]` (`macros/src/workflow_definitions.rs:422-447`) and a wait on `ctx.all_handlers_finished()` before returning (`workflow/src/workflow_context.rs:2310`) have no `.twf` form: record each in prose with its `file:line`.
- A queue built by an instance-key function (`sandbox_queue(sandbox_id)` → `format!("sandbox-{sandbox_id}")`) is a [family](./worker.md#per-instance-worker-families) worker.
- A Rust worker registers no Nexus service ([nexus-service-def.md](./nexus-service-def.md)): a `nexus service` comes from its handler SDK's code. A `NexusOperationOptions` names the endpoint, service and operation of the `nexus` call it builds, as strings ([nexus.md](./nexus.md)); follow a constant to its value. An endpoint from config cannot be resolved from code.
- A `WorkerOptions` built behind a helper or config layer: follow it to the `WorkerOptions::new` call.

## Concurrency

| Rust | `.twf` |
|------|--------|
| `#[signal]` / `#[update]` method whose body ends with `xs.add(…)` on an `Arrivals` | handler, its body less the `add` ([signal-handler.md](./signal-handler.md), [update-handler.md](./update-handler.md)); a counter it increments (`acks += 1`) and a waiter decrements once per take (`wait_condition(\|s\| s.acks > 0)` … `acks -= 1`) is an `Arrivals<()>`, while one never decremented, or reset, is plain `state:` |
| `take(ctx, of!(xs)).await?` | `await signal\|update Name -> (…)`, a tuple destructured after it read as its names; `Arrivals<()>` binds none ([await-signal.md](./await-signal.md)) |
| `let p = take(ctx, of!(xs));`, pinned and fused when an `await one` races it, `p.await?` later | `promise p <- signal\|update Name` ([promise.md](./promise.md)) |
| `workflows::join!(…)`; `join_all` over an iterator | `await all`, branches in argument order; a `for` fan-out inside ([await-all.md](./await-all.md)) |
| `workflows::select!`, or `futures::select_biased!`, which it delegates to (`workflow/src/workflows.rs:46-70`) | `await one`, cases in arm order: the first listed ready wins ([await-one.md](./await-one.md#cases)); a `take(…).fuse()` arm is a message case, a `ctx.wait_condition` arm a condition case, or a signal case over a counter |
| unbiased `futures::select!` or `tokio::select!` | `await one`, with a comment that a tie is won at random, not by the first listed (`futures-util` 0.3.34 `src/async_await/select_mod.rs:9`, `tokio` 1.54.1 `src/macros/select.rs:63-67`), which replay can resolve otherwise and the nondeterminism detector does not catch (`sdk/README.md:279-281`) |
| `let mut timer = ctx.timer(d);` just before the `select!`, `timer.cancel()` in every other arm | an inline `timer(d)` case; so is a timer dropped without `cancel()` or made in the arm (`_ = ctx.timer(d)`), though that losing timer runs on where spec 06 cancels it |
| a `ctx.timer(d)` bound before a loop and raced by `&mut` each round, or awaited after | `promise t <- timer(d)` with a `t:` case, which losing never cancels ([promise.md](./promise.md)) |
| a call bound to a variable unawaited (`let p = ctx.execute_activity(…);`, `ctx.timer`, `start_child_workflow`, `start_nexus_operation`), `.await` later | `promise` ([promise.md](./promise.md)); bound inside an `async { … }` block, it starts at its await, so it is a call there |
| a call awaited where it is made | synchronous call |
| a `bool` field a handler sets, awaited by `ctx.wait_condition(\|s\| s.flag)` | `condition` + `set` ([condition.md](./condition.md)); read as `await signal Name` only with a comment that repeated arrivals collapse into one |
| a `VecDeque` a handler pushes to, `ctx.wait_condition(\|s\| !s.pending.is_empty())` then `pop_front` per waiter | handler and `await signal\|update Name`, with a comment that waiters are served in poll order, not the order they began waiting ([await-signal.md](./await-signal.md)) |
| `start_child_workflow` with `ParentClosePolicy::Abandon` and `ChildWorkflowCancellationType::Abandon`, only the start awaited, never `.result()` | `detach workflow`; without the cancel type the caller's cancellation still reaches it, so record that in prose ([detach.md](./detach.md)) |
| `start_nexus_operation` with `NexusOperationCancellationType::Abandon`, only the start awaited, never `.result()` | `detach nexus` ([detach.md](./detach.md)) |
| `match ctx.continue_as_new(input, options)? {}` | `close continue_as_new(args)`, `input`'s `MultiArgsN` as the args ([close.md](./close.md)); onto another type (`ContinueAsNewOptions` `workflow_type`, `workflow/src/workflow_context/options.rs:718-720`), record it in prose |
| `ctx.timer(d).await` | `await timer(d)` ([await-timer.md](./await-timer.md)) |

## Codegen

- No forward variant generates code ([SKILL.md](../SKILL.md#orient)); `#[workflow_methods]` and `#[activities]` are read as written.
- A `build.rs` running `prost-build` or `tonic-build` compiles `.proto` messages; one wrapped in `ProstSerializable<T>` travels as `binary/protobuf` (`common-wasm/src/data_converters.rs:744-765`), so its payload type comes from the `.proto`.
- No Nexus contract is generated: Rust has no handler side.
- `build.rs` and `[build-dependencies]` name any other generator.
