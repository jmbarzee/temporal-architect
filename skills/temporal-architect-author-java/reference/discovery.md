# discovery

The Java signals the design skill's [reverse engineering](../../temporal-architect-design/reference/reverse-engineering.md#language-signals) reads code by. Call sites read backward through the [reference index](../SKILL.md#reference-index): a call on a `Workflow.newActivityStub` stub is an `activity` call, on a `Workflow.newChildWorkflowStub` stub a `workflow` call, on a `Workflow.newNexusServiceStub` stub a `nexus` call. Names read back through [Wire names](../SKILL.md#wire-names). Paths below are in `temporal-sdk` (`io/temporal/`), `nexus-sdk` (`io/nexusrpc/`) and `temporal-spring-boot-autoconfigure` (`io/temporal/spring/boot/`) source.

## Project roots

- A `pom.xml` or `build.gradle(.kts)` that depends on `io.temporal:temporal-sdk` or `io.temporal:temporal-spring-boot-starter` marks a root that uses Temporal. Its `groupId` and `artifactId` joined by `/` (`com.acme/orders`), else the repo path, is the path `twf mod init` takes; ask when neither fits. A Maven `<modules>` list or a Gradle `settings.gradle` `include` joins several modules, each its own root; a test-only module is not a root of its own.

## Registration

- `WorkerFactory.newInstance(client)` then `factory.newWorker("q", options?)` (`worker/WorkerFactory.java:77,169`) starts a worker on `q` in the client's namespace, `WorkflowClientOptions.Builder.setNamespace`, `"default"` when unset (`client/WorkflowClientOptions.java:23,234`). A namespace or queue read from config or the environment (`ClientConfigProfile.load()` then `toWorkflowClientOptions()`, `temporal-envconfig` `envconfig/ClientConfigProfile.java:47,212`; `System.getenv`) cannot be resolved from code: ask, or leave it to the stitch's topology. Its `WorkerOptions` and the factory's `WorkerFactoryOptions` read back through [worker.md](./worker.md#worker-options) into the namespace worker's `options:`.
- The types one `Worker` registers make one `worker` block ([worker.md](./worker.md#registration)), annotated `@sdk(java, "<path>")` with the file that registers them. A registrations method is that set, shared by the worker process and its tests: `registerApprovalTypes(Worker)` is `worker approvalTypes`, and its file is the path. With no `newWorker` applying it in the slice, there is no namespace or queue to recover; a test's worker gives the test's queue, not the deployment's, and workflows only a test registers are fixtures, not the design.
- `registerWorkflowImplementationTypes(Impl.class, …)` registers each impl's `@WorkflowInterface`, as does `registerWorkflowImplementationFactory(Iface.class, …)`; `registerActivitiesImplementations(instance, …)` every method of the instance's `@ActivityInterface`s (`worker/Worker.java:280,405,478`). A workflow is named by its interface's simple name, a nested `Batch.Audit` included, unless `@WorkflowMethod(name=…)` (`common/metadata/POJOWorkflowMethodMetadata.java:27`); an activity by its method name capitalized after `@ActivityInterface(namePrefix=)`, unless `@ActivityMethod(name=…)`.
- A `@SignalMethod`, `@UpdateMethod` or `@QueryMethod` on the workflow interface declares a `signal`, `update` or `query` of that workflow, named by its `name=` else the method name. Its params are the method's, positional, its result the update's or query's return, and its body the impl method's statements less the arrival record (`xs.add`, or a counter's `acks++`). The impl fields the handlers and the workflow method share, less its `Arrivals` and counters, are its `state:`. The annotation's `description` and `unfinishedPolicy` give `description` and `unfinished_policy`.
- An `@UpdateValidatorMethod` (`workflow/UpdateValidatorMethod.java`), a `DynamicWorkflow` or `DynamicActivity` implementation (`workflow/DynamicWorkflow.java`, `activity/DynamicActivity.java`), and a handler registered at runtime with `Workflow.registerListener` (`workflow/Workflow.java:866`), a `DynamicSignalHandler`, `DynamicQueryHandler` or `DynamicUpdateHandler` serving any unmatched name among them, have no `.twf` form: record each in prose with its `file:line`.
- A queue built by an instance-key method (`sandboxQueue(sandboxId)` → `"sandbox-" + sandboxId`) is a [family](./worker.md#per-instance-worker-families) worker.
- Each `registerNexusServiceImplementation(new Impl())` (`worker/Worker.java:497`) is a Nexus service on that worker: the `@ServiceImpl(service = Svc.class)` class names its contract, a `@Service` interface named by `@Service(name=)` else its simple name, whose methods are the operations, each `@Operation(name=)` else the method name (`nexus-sdk` `ServiceDefinition.java:20`, `OperationDefinition.java:27`). An `@OperationImpl` returning `WorkflowRunOperation.fromWorkflowMethod(…)` whose stub is `W`'s is an `async` operation backed by `W`; one returning `OperationHandler.sync(…)` a `sync` one, its body the lambda's ([nexus-service-def.md](./nexus-service-def.md)).
- `Workflow.newNexusServiceStub(Svc.class, NexusServiceOptions.newBuilder().setEndpoint("Ep")…)` names the endpoint and service of every `nexus` call made through it; follow a constant (`GreeterService.ENDPOINT`) to its value. An endpoint from config cannot be resolved from code.
- **Spring Boot.** `spring.temporal.namespace` is the root namespace, `"default"` when unset, and each `spring.temporal.namespaces` entry another (`autoconfigure/properties/NamespaceProperties.java:11,29`, `TemporalProperties.java:10,16`). Each `spring.temporal.workers` entry is a worker on its `task-queue`, registering its `workflow-classes`, `activity-beans` and `nexus-service-beans` (`autoconfigure/properties/WorkerProperties.java:13-17`). Under `workers-auto-discovery`, `@WorkflowImpl`, `@ActivityImpl` and `@NexusServiceImpl` add their class to the worker their `taskQueues` or `workers` name, creating it with defaults when no entry defines it (`WorkflowImpl.java:15-27`). A `${propertyKey}` queue resolves from `application.yml` or `.properties`, else from the environment, which cannot be resolved from code.
- A `Worker` built behind a DI container or factory: follow it to the `newWorker` call.

## Concurrency

| Java | `.twf` |
|------|--------|
| `@SignalMethod` / `@UpdateMethod` method whose body ends with `xs.add(…)` on an `Arrivals` | handler, its body less the `add` ([signal-handler.md](./signal-handler.md), [update-handler.md](./update-handler.md)); a counter it increments (`acks++`) and a waiter decrements once per take (`acks > 0` … `acks--`) is an `Arrivals<Boolean>`, while one never decremented, or reset, is plain `state:` |
| `xs.take()` | `await signal\|update Name -> (…)`, a record's accessors read as its names; `Arrivals<Boolean>` binds none ([await-signal.md](./await-signal.md)) |
| `Promise<T> p = xs.promise()`, `p.get()` later | `promise p <- signal\|update Name` ([promise.md](./promise.md)) |
| `Promise.allOf(…).get()`; over a list a `for` fills | `await all`, branches in argument order; a `for` fan-out inside ([await-all.md](./await-all.md)) |
| one `Workflow.await` over `xs.ready(t)`, an arrivals counter (`acks > 0`), `p.isCompleted()` and `boolean`s, then the first ready one in check order wins (`claim()`, `leave(t)`, `acks--`, `p.get()`) | `await one`, cases in that order ([await-one.md](./await-one.md)); a losing timer's scope cancelled after is part of the `await one`, not a statement, and a timer left running reads the same |
| `if (Workflow.await(d, () -> c))` | `await one` with a `timer(d)` case, then a `c` case: at a tie it returns false, so the timer wins (`internal/sync/SyncWorkflowContext.java:1390,1399`); false runs the timer case's body, true the condition's, and the timer it cancels when `c` wins is part of the `await one` (`:1375-1393`) |
| `Promise.anyOf(…)` | `await one`, with a comment that the first to complete wins, not the first listed: it completes in callback order (`internal/sync/CompletablePromiseImpl.java:25-31`), and a timer or activity result of the same workflow task beats a signal ([await-one.md](./await-one.md)) |
| a `boolean` field set by a handler, awaited once by `Workflow.await(() -> flag)` | `condition` + `set` ([condition.md](./condition.md)); read as `await signal Name` only with a comment that repeated arrivals collapse into one |
| a `WorkflowQueue` a handler `put`s into, `take()`n in the workflow (`workflow/Workflow.java:817`) | handler and `await signal\|update Name`; taken by several threads, with a comment that waiters are served in thread-creation order, not the order they began waiting (`internal/sync/WorkflowQueueImpl.java:23-26`, [await-signal.md](./await-signal.md)) |
| `Async.function(stub::m, …)` or `Workflow.newTimer(d)` held, `get()` later; `Workflow.startNexusOperation(…).getResult()` | `promise` ([promise.md](./promise.md), [nexus.md](./nexus.md)) |
| a call on the stub itself | synchronous call |
| `Async.procedure` or `Async.function` on a child stub with `PARENT_CLOSE_POLICY_ABANDON`, only `Workflow.getWorkflowExecution(stub).get()` waited on, the result never read | `detach workflow`; without `ChildWorkflowCancellationType.ABANDON` the caller's cancellation still reaches it, so record that in prose ([detach.md](./detach.md)) |
| `WorkflowClient.start(client.newWorkflowStub(…)::run, …)` in a sync Nexus handler, the result never read | `detach workflow` ([detach.md](./detach.md)) |
| `Workflow.startNexusOperation(stub::op, arg)` on a stub with `NexusOperationCancellationType.ABANDON`, `getExecution().get()` only, never `getResult()` | `detach nexus` ([detach.md](./detach.md)) |
| `return Workflow.newContinueAsNewStub(W.class).run(args…)` in `W`, or `Workflow.continueAsNew(args…)` | `close continue_as_new(args)` ([close.md](./close.md)); onto another type (`continueAsNew(workflowType, options, args…)`, `workflow/Workflow.java:628`), record it in prose |
| `Workflow.sleep(d)` | `await timer(d)` ([await-timer.md](./await-timer.md)) |

## Codegen

- No forward variant generates code ([SKILL.md](../SKILL.md#orient)).
- Protobuf messages travel through the default converter's `ProtobufJsonPayloadConverter` and `ProtobufPayloadConverter` (`common/converter/DefaultDataConverter.java:19-20`): the payload types come from the `.proto` the build's protobuf plugin compiles.
- A `@Service` contract generated by `nexus-rpc-gen` from a `*.nexusrpc.yaml` definition ([nexus-rpc-gen](https://github.com/nexus-rpc/nexus-rpc-gen)): read the definition, not the interface, for the `nexus service` and its operations.
- `pom.xml` plugins and Gradle tasks name any other generator.
