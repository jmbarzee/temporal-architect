# Primitives across SDKs

**This applies only where `twf check` reports `CROSS_SDK_CALL`**: a workflow, activity or Nexus call, or a signal send, whose caller runs on a worker in one SDK and whose callee runs on a worker in another, and a call's return. Otherwise it does not apply; within one SDK, each author maps the `.twf` types by its own SDK's conventions.

The SDKs' default data converters write JSON, but not the same JSON for every `.twf` primitive. `string`, `bool`, a finite `float` and an `int` within ±2^53 cross unchanged, alone or in a `list`, `map` or struct. The types below do not.

## The order

1. **Prefer a codec**: a data converter / payload codec at that boundary, on both sides, that fixes one wire form for the type.
2. Without one, either:
   - (a) **prefer the representation of the SDK with the far bulkier implementation** (the larger workflow ecosystem), so the smaller side adapts; or
   - (b) **convert explicitly** at the call or return that crosses the boundary.

**The check:** a workflow tree or cluster strongly prefers its own language's standards and conventions. The case to avoid is many workflows using an atypical type to handle conversion at a few points.

## Per type

Read from the default converters of Go SDK v1.50.0, TypeScript SDK 1.25.0, Python SDK 1.35.0, Java SDK 1.40.0 (Jackson 2.15.4), .NET SDK 1.21.1, Ruby SDK 1.10.1, Rust SDK 1.1.2, PHP SDK 2.20, Swift SDK 1.5.0, Clojure SDK 2.4.1 (jsonista 1.0.1), Haskell SDK `e57a0ae` (Aeson), Perl SDK `55816a1` and Elixir SDK `d2749c7`; for another SDK, read its converter.

Two SDKs break the JSON baseline before any type does:

- **Clojure**'s default converter writes every non-nil value as Nippy, labelled `binary/plain`, which no other SDK reads. At a crossing the Clojure side needs its JSON converter (`temporal.converter.json`) or a codec; the rows below give that JSON converter.
- **Elixir** sends every binary, so every `string`, as `binary/plain` raw bytes, not a JSON string, which Go, Rust and Swift reject as a `string` param; `nil` goes out as the string `"nil"`; a tuple, or a struct holding one (`DateTime`), falls to `binary/erlang`, which no other SDK reads.

| `.twf` | Hazard |
|---|---|
| field names | Every converter writes a field under its name as declared, with no case transform, so each language's convention reaches the wire: Go an exported `Request` (unless tagged), .NET PascalCase, Python and Rust snake_case, Java, TypeScript, PHP, Swift and Haskell camelCase; Ruby, Perl and Elixir write a hash's or map's keys as written, and Clojure a keyword's name (kebab-case by idiom). Java also writes a bean getter as a field (`getOtherName()` → `"otherName"`). |
| `int` past 2^53 | JavaScript decodes a JSON number as a double (the TypeScript converter is `JSON.parse`), exact only to 2^53−1; a larger value (an int64 ID, a nanosecond count) silently rounds. A `bigint` does not serialize at all. Go, Java, .NET, Rust, PHP, Swift, Clojure, Haskell's `Int` and Perl carry the full int64 range, and Python, Ruby and Elixir an integer of any size, so the hazard is a JavaScript reader. Perl decodes an integer above 2^64−1 or below −2^63 as a rounded float. |
| `decimal` | `.twf` `decimal` is exact; no default converter carries it exactly to every other SDK. As a JSON number it decodes to a binary double in JavaScript; Go's `decimal.Decimal` and Rust's `rust_decimal::Decimal` write a quoted string: exact, but a string to the other SDKs; Python's converter does not encode `decimal.Decimal`; Java's `BigDecimal` and .NET's `decimal` write a bare JSON number keeping its scale (`1.10`), exact into a decimal type but rounded when read as a JavaScript or Python float, and Clojure's `BigDecimal` too, though it reads one back as a `Double`; Haskell's `Scientific` and Swift's `Decimal` write a bare number, exact in value with its scale dropped (`1.1`); Ruby's `BigDecimal` writes a string in scientific form (`"0.11e1"`); PHP and Perl have no decimal type the converter writes, and Elixir's `Decimal` goes out as its struct's fields, so a string by convention. |
| `duration` | No shared form. Go's `time.Duration` encodes as a bare integer of nanoseconds (past 2^53 ns, about 104 days, it also hits the JavaScript `int` hazard), and so does PHP's `DateInterval` inside a DTO; Python's converter does not encode `timedelta`; Java's and Clojure's `Duration` encode as a number of seconds with a 9-digit fraction (`5400.000000000`); .NET's `TimeSpan` as a string in its constant format (`"00:05:00.0000001"`); Rust's `Duration` as an object (`{"secs":5400,"nanos":0}`); Haskell's `Duration` as a protobuf-JSON string (`"5400s"`); Swift's `Duration` as a two-element array of its 128-bit attosecond count (`[292,13550730476810928128]`), which no other SDK reads; JavaScript, Ruby, Perl and Elixir have no duration type the converter writes. |
| `time` | ISO 8601 strings that disagree. Go encodes RFC 3339 to nanoseconds and rejects a timestamp without an offset; Python writes `datetime.isoformat()` (no offset on a naive `datetime`, microseconds at most); Java, Clojure and Rust write an `Instant` or `DateTime<Utc>` in UTC with `Z`, to nanoseconds, the fraction in groups of 3 digits (`.100Z`) and none on a whole second, and Clojure reads one back as a string; .NET writes a `DateTimeOffset` with its offset and up to 7 fractional digits, trailing zeros trimmed (`.1+00:00`, none on a whole second; no offset from a `DateTime` of unspecified kind); Haskell writes a `UTCTime` with `Z` and up to 12 fractional digits, trailing zeros trimmed; PHP writes RFC 3339 with its offset and Swift a `Date` in UTC with `Z`, both in whole seconds; Ruby writes a `Time` as its `to_s` (`"2026-11-08 12:00:00 UTC"`), not ISO 8601 and without sub-seconds; JavaScript writes a `Date` to milliseconds and decodes it as a plain string, not a `Date`; Perl's converter rejects a `DateTime` and Elixir's falls to `binary/erlang`, so a string by hand. |
| `bytes` | Crosses only as a whole argument or result: every converter sends a top-level byte value raw (`binary/plain`): in Ruby only an `ASCII-8BIT` `String`, in Perl only a `Temporalio::Payload::RawBytes`, in Haskell only through its `Binary` codec. Nested in a struct, list or map it diverges: Go, Java, .NET, Swift and Clojure write a base64 string, Python and Rust a list of ints (and Python cannot decode a base64 string), JavaScript a `Uint8Array` as an object keyed by index; PHP writes a `Bytes` property as `[]`, losing it; Ruby, Perl and Elixir write a byte string as text (on invalid UTF-8 Ruby raises and Elixir sends the whole payload as `binary/erlang`) and Haskell's `ByteString` has no JSON form, so base64 by hand in those four. |
| signal and update params | Go's author wraps a signal's params in one struct, sent as one payload even for one param; Swift and Clojure send one payload per call, several params as one struct or map, and Swift sends a call without params as one empty payload and rejects zero payloads; TypeScript, Python, Java, .NET, Ruby, Rust, PHP, Perl, Haskell and Elixir (which has no updates) send one payload per param, positionally, and so do Go's updates. So a signal with params disagrees between Go, Swift or Clojure and the others, even with one, and an update between Swift or Clojure and the others. |
