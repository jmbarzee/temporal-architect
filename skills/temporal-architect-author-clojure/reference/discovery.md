# discovery

The Clojure signals the design skill's [reverse engineering](../../temporal-architect-design/reference/reverse-engineering.md#language-signals) reads code by. Call sites read backward through the [reference index](../SKILL.md#reference-index): `a/invoke` is an `activity` call, `w/invoke` a `workflow` call. Names read back through [Wire names](../SKILL.md#wire-names). sdk-java interop (`Workflow/…`, a `WorkerFactory` built by hand) reads back through [author-java's discovery](../../temporal-architect-author-java/reference/discovery.md), less its Nexus rows: the SDK has no Nexus API. Paths below are in the SDK's source at `v2.4.1`; sdk-java paths are in `temporal-sdk` (`io/temporal/`) at `v1.40.0`.

## Project roots

- A `project.clj` whose `:dependencies`, a `deps.edn` whose `:deps` or an alias's `:extra-deps`, or a `pom.xml` whose `<dependencies>` hold `io.github.manetu/temporal-sdk` marks a root that uses Temporal. Its `defproject` symbol (`com.acme/orders`), or a pom's `groupId` and `artifactId` joined by `/`, else the repo path (a `deps.edn` names none), is the path `twf mod init` takes; ask when neither fits. A sibling project with its own project file, a `deps.edn` `:local/root` dependency, or a pom's `<modules>` entry is its own root; a test-only alias or module is not.

## Registration

- `(worker/start client opts factory-opts?)` (`src/temporal/client/worker.clj:168-188`) starts a worker on `(:task-queue opts)` through `namify`, so `:orders` is `"orders"` and `::q` is `"my.ns/q"` (`src/temporal/internal/utils.clj:152-156`), in the client's namespace, `(c/create-client {:namespace …})` (`src/temporal/client/options.clj:33`), `"default"` when unset (sdk-java `client/WorkflowClientOptions.java:23,234`). A namespace or queue read from config or the environment (`System/getenv`, an EDN file) cannot be resolved from code: ask, or leave it to the stitch's topology. The map's other keys, the factory options `worker/start` takes third, and the client's `:identity` read back through [worker.md](./worker.md#worker-options) into the namespace worker's `options:`; a worker built by hand and registered with `worker/init` (`:15-35`) takes its queue and options from its `.newWorker` call ([worker.md](./worker.md#interop-sticky-timeout-identity-versioning)).
- The `:dispatch` of one options map makes one `worker` block ([worker.md](./worker.md#registration)), annotated `@sdk(clojure, "<path>")` with the file that defines the map: `(def batch-types {… :dispatch {:workflows [Batch Audit Archive] :activities [Count Store]}})` is `worker batchTypes`. With no `worker/start` applying the map in the slice, there is no namespace or queue to recover; a test's `e/start` (`src/temporal/testing/env.clj:64-84`) gives the test's queue, not the deployment's, and workflows only a test registers are fixtures, not the design.
- **No `:dispatch`** registers every `defworkflow` and `defactivity` of every namespace loaded in the JVM when the worker starts (`src/temporal/client/worker.clj:22-24`, `src/temporal/internal/utils.clj:46-56`): the `worker` block lists the `def*` forms of every namespace the worker's process requires, transitively, with a comment that the set is whatever that process has loaded.
- A `defworkflow` or `defactivity` is named by its var, verbatim and without its namespace (`src/temporal/workflow.clj:222-224`, `src/temporal/activity.clj:255-257`). A kebab-case var registers a name `.twf` cannot spell, since an identifier admits no hyphen (`twf spec tokens-and-keywords`): ask the user, never rename it silently. The params are the keys its one map destructures, `{:keys [order item]}` → `(order, item)`, an activity's after the `:ctx` it takes first; the result is the body's value. Keys camelCase back (`:tracking-id` → `trackingId`), and a value types back through [types.md](./types.md), else from its callers and tests, else `any`. A map carries no type name: name a user type from its producer (`BatchResult`), or ask.
- The one `s/register-signal-handler!` declares a `signal` for each name it dispatches on, by `case` or `(= "Ack" signal-name)`; `w/register-query-handler!` and `w/register-update-handler!` a `query` or `update` for each `case` keyword. Its params are the args map's keys, its result the branch's value, and its body the branch less the arrival record (`arr/add!`, or a counter's `(swap! acks inc)`). The `defworkflow`'s `let` atoms the handlers and the body share, less its arrivals and counters, are its `state:`. An update `:validator` that rejects names outside the `case` is that dispatch, with no `.twf` form; one that checks the args is prose with its `file:line`.
- A `Workflow/registerListener` of a `DynamicSignalHandler`, `DynamicUpdateHandler` or `DynamicQueryHandler` reads as the SDK's handler, with `getUnfinishedPolicy` giving each name's `unfinished_policy` and `getDescription` the `description` ([signal-handler.md](./signal-handler.md#handler-options)). A handler that serves any name rather than dispatching on it has no `.twf` form: record it in prose with its `file:line`.
- `s/create-signal-chan` registers the workflow's one signal handler, queueing every payload by name (`src/temporal/internal/signals.clj:13-22,32-36`): it declares a bodiless `signal` for each name its `s/<!` and `s/poll` calls read (`"Ack"`, or a keyword through `namify`).
- An ID function passed as `:workflow-id` (`(str "ship-" order-id "-" item-id)`) is the callee's `id_scheme:` (`"ship-{orderId}-{itemId}"`), and the start-options map beside it its `default_options:` ([workflow-def.md](./workflow-def.md#id_scheme)). A map shared by every call of one definition is its `default_options:`, and a call's `merge` over it the call's `options:` ([options.md](./options.md#definition-level-default_options)).
- A queue built by an instance-key function (`(sandbox-queue sandbox-id)` → `(str "sandbox-" sandbox-id)`) is a [family](./worker.md#per-instance-worker-families) worker.

## Concurrency

| Clojure | `.twf` |
|---------|--------|
| a handler branch ending with `(arr/add! xs v)` | handler, its branch less the `add!` ([signal-handler.md](./signal-handler.md), [update-handler.md](./update-handler.md)); a counter it increments (`(swap! acks inc)`) and a waiter decrements once per take (`(pos? @acks)` … `(swap! acks dec)`) is the arrivals of a no-param signal, while one never decremented, or reset, is plain `state:` |
| `(arr/take! xs)` | `await signal\|update Name -> (…)`, the taken map's keys as its names; a `true` arrival binds none ([await-signal.md](./await-signal.md)) |
| `(arr/promise! xs)`, `@p` later | `promise p <- signal\|update Name` ([promise.md](./promise.md)) |
| `@(tp/all [...])`; over a `mapv` or `for` | `await all`, branches in vector order; a `for` fan-out inside ([await-all.md](./await-all.md)) |
| one `w/await` over `arr/ready?` tickets, an arrivals counter (`(pos? @acks)`), `(.isCompleted promise)`, `(p/done? p)` and condition atoms, then the first ready one in check order wins (`arr/claim!`, `arr/leave!`, `(swap! acks dec)`, `@p`) | `await one`, cases in that order ([await-one.md](./await-one.md)); a losing inline timer, one started for this `await one` alone (the `inline-timer` scope), reads as a `timer(d)` case whether its scope is cancelled after or it is left running; a `w/new-timer` or `Workflow/newTimer` started earlier and checked across rounds or read after is `promise t <- timer(d)` with a `t:` case, which losing never cancels (spec 06) |
| `(w/await d pred)`, and the timed receive `(s/<! ch "X" d)` built on it (`src/temporal/signals.clj:41-44`) | `await one` with a `timer(d)` case, then the `pred` or `signal X` case: at a tie it returns false, so the timer wins (sdk-java `internal/sync/SyncWorkflowContext.java:1390,1399`); false (`nil` from `<!`) runs the timer case's body, true (the payload) the other's, and a lost receive leaves the arrival on the channel |
| `(tp/race [...])` | `await one`, with a comment that the first to complete wins, not the first listed: it is `Promise.anyOf` (`src/temporal/promise.clj:61-75`), which completes in callback order (sdk-java `internal/sync/CompletablePromiseImpl.java:25-31`), and a timer or activity result of the same workflow task beats a signal ([await-one.md](./await-one.md)) |
| `(s/<! ch "X")` | `await signal X`; taken by several threads, with a comment that waiters are served in thread-creation order, not the order they began waiting ([await-signal.md](./await-signal.md)) |
| `(s/poll ch "X")` | no `.twf` form, a take that never waits (`src/temporal/signals.clj:28-32`): prose with its `file:line` |
| a boolean atom a handler sets, awaited once by `(w/await #(deref flag))` | `condition` + `set` ([condition.md](./condition.md)); read as `await signal Name` only with a comment that repeated arrivals collapse into one |
| `(a/invoke …)`, `(w/invoke …)` or `(w/new-timer d)` held, `@` later | `promise` ([promise.md](./promise.md)) |
| `@(a/invoke …)`, `@(w/invoke …)` | synchronous call |
| an untyped child stub with `PARENT_CLOSE_POLICY_ABANDON`, `.executeAsync`, only `(.get (.getExecution stub))` waited on, the result never read (the corpus's `detach-workflow!`) | `detach workflow`; without `ChildWorkflowCancellationType/ABANDON` the caller's cancellation still reaches it, so record that in prose ([detach.md](./detach.md)) |
| `(w/invoke X params {:parent-close-policy :abandon …})` never dereferenced | `detach workflow`, with a comment that nothing waits for the start, so a failed start goes unseen ([detach.md](./detach.md)) |
| an untyped child stub's `.executeAsync`, then `(.signal stub "Name" …)` | `promise h <- workflow X`, then `signal h.Name(args)`; `(s/>! id "Name" args)` or `w/signal-external` is `signal Type.Name(args)` with `id:`, the type the ID's scheme belongs to ([signal-send.md](./signal-send.md)) |
| `(w/continue-as-new params)` | `close continue_as_new(args)` ([close.md](./close.md)) |
| an uncaught `(throw+ {…})` | `close fail(…)` ([close.md](./close.md)) |
| `(w/sleep d)` | `await timer(d)` ([await-timer.md](./await-timer.md)) |
| `(w/await w/every-handler-finished?)` before the body returns | no `.twf` form: the forward mapping writes it ([update-handler.md](./update-handler.md)) |

## Codegen

- No forward variant generates code ([SKILL.md](../SKILL.md#orient)).
- The SDK has no codegen, and its default converters are Null, Nippy and JSON (`src/temporal/converter/default.clj:15-18`): no protobuf payload path to read types from.
- A project file's `:plugins` and `:prep-tasks`, a `deps.edn` alias's `:exec-fn`, or a pom's `<plugins>` name any other generator.
