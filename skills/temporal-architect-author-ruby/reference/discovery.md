# discovery

The Ruby signals the design skill's [reverse engineering](../../temporal-architect-design/reference/reverse-engineering.md#language-signals) reads code by. Call sites read backward through the [reference index](../SKILL.md#reference-index): `Workflow.execute_activity` is an `activity` call, `Workflow.execute_child_workflow` a `workflow` call, a Nexus client's `execute_operation` a `nexus` call, and their keywords read back through [options.md](./options.md). Names read back through [Wire names](../SKILL.md#wire-names), values through [types.md](./types.md): a `Data` with `to_json` and `from_h` is a user type, and a `String` member is a `decimal`, `time` or nested `bytes` only where its conversions (`BigDecimal(s)`, `Time.iso8601(s)`, `unpack1('m0')`) or a name say so. Ruby declares no types: read a param's type from its `from_h`, its use, or the tests' values. Paths below are in `temporalio` source (`lib/temporalio/`).

## Project roots

- A `Gemfile` or `*.gemspec` that depends on `temporalio` marks a root that uses Temporal; the community `temporal-ruby` gem is another SDK, which this skill does not map. The gemspec's `name`, else a Rails app's `config/application.rb` module, else the repo path, is the path `twf mod init` takes; ask when none fits. Each `Gemfile` is its own root; a Rails app, its `lib/`, scripts and initializers included, is one.

## Registration

- `Temporalio::Worker.new(client:, task_queue:, workflows: […], activities: […])` (`worker.rb:463-467`) starts a worker on `task_queue` in its client's namespace, `Client.connect(target_host, namespace, …)`'s required second argument (`client.rb:110-112`). A namespace or queue read from config or the environment (`EnvConfig::ClientConfig.load_client_connect_options`, `env_config.rb:285`; `ENV`) cannot be resolved from code: ask, or leave it to the stitch's topology. Its other keywords read back through [worker.md](./worker.md#worker-options) into the namespace worker's `options:`, `tuner: Worker::Tuner.create_fixed(…)` into the three slot counts and `deployment_options:` into `versioning: deployment`.
- The types one `Worker` registers make one `worker` block ([worker.md](./worker.md#registration)), annotated `@sdk(ruby, "<path>")` with the file that builds it. A factory method returning the `Worker` is that set, shared by the worker process and its tests: `def self.approval_types(client)` is `worker approvalTypes`, and its file is the path. An `activities:` default in the factory (`activities: [Count, Store]`) is the deployment's set; a test's stand-ins, its queue, and workflows only a test registers are fixtures, not the design. `Worker.run_all(w1, w2)` (`worker.rb:138`) runs several workers, each its own block.
- **Rails.** An initializer (`config/initializers/`) usually builds only the client; the worker is `Worker.new` in a script run by `bin/rails runner`, requiring its workflows and activities first (`samples-ruby` `rails_app/script/temporal_worker.rb`; `temporal-developer` `references/ruby/advanced-features.md` § Rails Integration). Follow a client or queue held by an app module (`TemporalClient.task_queue`) to its value.
- A workflow is named by its `Workflow::Definition` subclass's unqualified class name, a wrapping `module` dropped, unless `workflow_name 'X'` (`workflow/definition.rb:552`); an activity by its `Activity::Definition` subclass's, unless `activity_name 'X'` (`activity/definition.rb:109`). A signal, query or update is named by its `name:`, else its method name, so a bare snake_case handler is a snake_case `.twf` name (`workflow/definition.rb:303,312,321`).
- A `workflow_signal`, `workflow_query` or `workflow_update` method declares a `signal`, `query` or `update` of that workflow; `workflow_query_attr_reader :status` declares a query `status` returning `@status` (`workflow/definition.rb:92-108`). Its params are the method's, positional, its result the update's or query's return, and its body the method's statements less the arrival record (`@xs.add`, or a counter's `@acks += 1`). The instance variables `initialize` sets that the handlers and `execute` share, less its `Arrivals` and counters, are its `state:`; `execute`'s params are the workflow's. The keywords `description:` and `unfinished_policy:` give `description` and `unfinished_policy`.
- A `workflow_update_validator` (`workflow/definition.rb:218`), a `workflow_dynamic` workflow or `activity_dynamic` activity (`workflow/definition.rb:37`, `activity/definition.rb:65`), a `dynamic: true` handler (`workflow/definition.rb:140-148`), and a handler set at runtime through `Workflow.signal_handlers`, `query_handlers` or `update_handlers` `[]=` (`workflow.rb:364-368,385-389,507-511`) have no `.twf` form: record each in prose with its `file:line`.
- A queue built by an instance-key method (`def self.sandbox_queue(sandbox_id) = "sandbox-#{sandbox_id}"`) is a [family](./worker.md#per-instance-worker-families) worker.
- A class method rendering a workflow ID (`def self.workflow_id(order_id, item_id)`), or an interpolated `id:` at a start, is the started type's `id_scheme:` ([workflow-def.md](./workflow-def.md#id_scheme)); a start-options `Hash` that every client start splats gives that type's ID policies, and a frozen `DEFAULTS` `Hash` on a definition, splatted by every call, its `default_options:`, the keywords a call writes after the splat that call's `options:` ([options.md](./options.md#definition-level-default_options)).
- Ruby hosts no Nexus service ([nexus-service-def.md](./nexus-service-def.md)): a `nexus service` a Ruby workflow calls lives in another SDK's slice. `Workflow.create_nexus_client(endpoint: 'Ep', service: 'Svc')` names the endpoint and service of every `nexus` call made through it, and each `execute_operation` or `start_operation` string its operation; follow a constant to its value. An endpoint from config cannot be resolved from code.
- A `Worker` built behind a factory or DI container: follow it to the `Worker.new` call.

## Concurrency

| Ruby | `.twf` |
|------|--------|
| `workflow_signal` / `workflow_update` method that ends with `@xs.add(…)` on an `Arrivals`, an update's result after it | handler, its body less the `add` ([signal-handler.md](./signal-handler.md), [update-handler.md](./update-handler.md)); a counter it increments (`@acks += 1`) and a waiter decrements once per take (`@acks.positive?` … `@acks -= 1`) is a no-param signal's arrivals, while one never decremented, or reset, is plain `state:` |
| `@xs.take_now` | `await signal\|update Name -> (…)`, a `Data` arrival's members read as its names; `add(nil)` binds none ([await-signal.md](./await-signal.md)) |
| a handler that appends to a pending `Array`, and a `wait_condition { !@pending.empty? }` that `shift`s | the same as `Arrivals`: handler and `await signal\|update Name`; it loses nothing and serves waiters in the order they began ([await-signal.md](./await-signal.md)) |
| `p = @xs.take`, `p.wait` later | `promise p <- signal\|update Name` ([promise.md](./promise.md)) |
| `Workflow::Future.new { @xs.take_now }`, waited later | `promise p <- signal\|update Name`, with a comment that it begins waiting when its fiber first runs, not at its binding, so a later `await` on the same message can take first ([promise.md](./promise.md)) |
| `Workflow::Future.all_of(…).wait`; over futures a `map` builds | `await all`, branches in argument order; a `for` fan-out inside ([await-all.md](./await-all.md)); `try_all_of` waits out every branch's failure (`workflow/future.rb:59-64`): say so in a comment |
| one `wait_condition` over `@xs.ready?(t)`, a counter (`@acks.positive?`), `f.done?` (a nested `all_of` future included) and flags, then the first ready one in check order wins (`claim`, `leave`, `@acks -= 1`, `f.wait`) | `await one`, cases in that order ([await-one.md](./await-one.md)); a losing inline timer, a `Future` over `Workflow.sleep(d, cancellation:)` started for this `await one` alone, reads as a `timer(d)` case whether its `cancel_timer.call` follows or it is left running; a `Future` over `Workflow.sleep(d)` started earlier and checked across rounds or read after is `promise t <- timer(d)` with a `t:` case, which losing never cancels (spec 06) |
| `Workflow.timeout(d) { Workflow.wait_condition { c } }`, rescuing `Timeout::Error` | `await one` with a `timer(d)` case, then a `c` case: its timer raises into the waiter while the activation applies the timer's job, before any handler runs, so at a tie the timer wins (`internal/worker/workflow_instance/context.rb:339-358`; the corpus's `test_workflow_timeout_is_not_await_one`); the `rescue` runs the timer case's body, the code after the block the condition's, and the timer it cancels when `c` wins is part of the `await one` (`:354-358`). Unrescued, `Timeout::Error` fails the run (`workflow.rb:486-488`): the timer case is `close fail` |
| `Workflow::Future.any_of(…)` or `try_any_of(…)` | `await one`, with a comment that the first listed done future wins (`workflow/future.rb:17-22,47-52`), but every ready take has already claimed its arrival, the losers' included (the corpus's `test_future_any_of_over_takes_is_not_await_one`) |
| a `true` / `false` instance variable set by a handler, awaited once by `Workflow.wait_condition { @flag }` | `condition` + `set` ([condition.md](./condition.md)); read as `await signal Name` only with a comment that repeated arrivals collapse into one |
| `Workflow.wait_condition { Workflow.all_handlers_finished? }` before a return | no `.twf` form: in-flight handlers finishing before the `close` ([composite-patterns.md](./composite-patterns.md)) |
| `Workflow::Future.new { Workflow.execute_activity(…) }`, `{ Workflow.execute_child_workflow(…) }`, `{ Workflow.sleep(d) }` or `{ client.execute_operation(…) }` held, `wait` or `result` later | `promise` ([promise.md](./promise.md)) |
| `h = Workflow.start_child_workflow(…)`, `h.result` read later | `promise h <- workflow …`; `h.signal` sends to it ([signal-send.md](./signal-send.md#handle-head-a-child)) |
| a call on `Workflow` or the Nexus client itself | synchronous call |
| `Workflow.start_child_workflow(…, parent_close_policy: ParentClosePolicy::ABANDON)`, the handle's `result` never read | `detach workflow`; without `cancellation_type: ChildWorkflowCancellationType::ABANDON` the caller's cancellation still reaches it, so record that in prose ([detach.md](./detach.md)) |
| `client.start_workflow(…)` outside a workflow, the handle's `result` never read | not a statement: an activity body's pseudocode, or the design's entry point ([detach.md](./detach.md)) |
| `client.start_operation('Op', arg, cancellation_type: NexusOperationCancellationType::ABANDON)`, the handle's `result` never read | `detach nexus` ([detach.md](./detach.md)) |
| `Workflow.external_workflow_handle(id, run_id:).signal(W.handler, …)`; `id` from `Workflow.info.parent` | `signal W.Name(…)`, `Name` the handler's wire name, with `id:` (and `run_id:`); `id: parent` ([signal-send.md](./signal-send.md#type-head-by-id)) |
| `return v` from `execute`; `raise Error::ApplicationError`, or a type `workflow_failure_exception_type` lists (`workflow/definition.rb:71`) | `close complete(v)`; `close fail(…)`. Any other exception fails the workflow task, which retries: not a `close` ([close.md](./close.md)) |
| `raise Workflow::ContinueAsNewError.new(args…)` | `close continue_as_new(args)` ([close.md](./close.md)); with `workflow:` another type (`workflow.rb:668,694`), record it in prose |
| `Workflow.sleep(d)` | `await timer(d)` ([await-timer.md](./await-timer.md)). A bare `sleep` is not a timer: `Kernel#sleep` is a default illegal workflow call (`worker.rb:326-327`) and raises; report it as a defect |
| `Activity::Context.current.heartbeat(details)` | `heartbeat(details)` ([heartbeat.md](./heartbeat.md)) |

## Codegen

- No forward variant generates code ([SKILL.md](../SKILL.md#orient)).
- Protobuf messages travel through the default converter's `JSONProtobuf` and `BinaryProtobuf` (`converters/payload_converter.rb:24-31`): the payload types come from the `.proto` that the generated files, headed `# Generated by the protocol buffer compiler.  DO NOT EDIT!`, were compiled from.
- RBI files `tapioca` generates are the gems' signatures, not design (`samples-ruby` `sorbet_generic/README.md`); a Sorbet `sig` on `execute` or a handler gives its param types (`sorbet_generic/say_hello_workflow.rb:19`).
- A `Rakefile` task or Makefile names any other generator.
